## 四、实施方案（关键技术方案）

1. **多文件拆分、经典脚本加载**：不使用 ES Module，保证 `file://` 双击打开也能运行；脚本按 `utils → config → editor → templates → theme → ai → app` 顺序加载。
2. **微信兼容策略**：微信后台粘贴会丢弃 `<style>`/`class`，因此排版与主题统一输出**行内样式**；模板虽以 `<style>` 呈现，但提供「一键内联样式」转换为行内样式。
3. **AI 接入**：统一 OpenAI 兼容协议（`POST {baseUrl}/v1/chat/completions`），支持 SSE 流式；配置仅存本地 `localStorage`，不上传。
4. **生图双通道**：
   - 内置通道：`https://trae-api-cn.mchost.guru/api/ide/v1/text_to_image?prompt=&image_size=`（免 Key）；
   - 自填通道：OpenAI 兼容 `/v1/images/generations`（支持 `url` 或 `b64_json` 返回）。
5. **AI 学习模板**：先用规则从 HTML/CSS 中提取设计令牌（主色、辅色、字体、圆角、间距、标题风格），再交由 AI 归纳为「风格说明 + 示例片段」，落库为「我的风格」。
6. **容错**：所有 AI 调用失败均给出明确 Toast 提示并保留手动兜底（离线规则排版、粘贴源码导入）。
7. **代码规范**：所有函数补充中文函数级注释（功能、参数、返回值）。

## 六、使用说明（快速上手）

### 6.1 启动方式
- 方式一（最简单）：双击 `index.html` 用 Chrome / Edge 打开即可。
- 方式二（推荐，避免个别浏览器对本地文件的安全限制）：
  ```powershell
  cd c:\Users\Administrator\Desktop\wxeditor
  python -m http.server 8131
  ```
  浏览器访问 `http://127.0.0.1:8131/index.html`。

### 6.2 配置 AI（一次即可，存本机）
1. 点右上角「AI 助手」→「设置」；
2. 选一个厂商预设（DeepSeek / 通义千问 / 智谱 / Kimi / OpenAI / 本地 Ollama）；
3. 填 API Key（与模型名），点「保存设置」→「测试连接」；
4. 顶部出现绿色「AI 已配置 · 模型名」即成功。

### 6.3 常用流程
| 目标 | 操作 |
| --- | --- |
| AI 写方案 | AI 助手 →「写方案」→ 填主题/类型/字数 → 生成文章（可勾选「生成后自动排版」） |
| 粘贴现成文稿美化 | AI 助手 →「排版」→「Markdown / 纯文本一键转排版」→ 转换并插入 |
| 换整体风格 | 左栏「主题」→ 选主题 → 点「应用当前主题到全文」 |
| 微信兼容 | 排版后点「一键内联样式」，再到公众号后台粘贴 |
| AI 配图 | AI 助手 →「生图」→ 填提示词（或点「根据文章生成配图提示词」）→ 生成并插入 |
| 学别人的排版 | AI 助手 →「风格学习」→ 选模板或粘贴 HTML → 学习 → 保存为「我的风格」→ 应用 |
| 局部润色 | 正文里选中文字 → 浮出工具条 → 润色/扩写/缩写/改写/纠错/翻译 |
| Markdown 写作 | 工具栏点「MD」进入双栏模式 → 左侧写 Markdown → 右侧实时预览 → 点「同步为富文本」套用主题与排版 |
| 调整排版细节 | 左栏「排版」→ 改字号/行高/段间距/标题样式/引用样式/代码主题 → 点「应用排版到全文」 |
| 外链转脚注 | 左栏「排版」→ 勾选「外链转为文末脚注」→ 应用排版 |
| 公式与图表 | Markdown 中用 `$..$`、`$$..$$`、```mermaid 代码块``` → 勾选「自动渲染公式/图表」或点「渲染公式与图表」 |
| 保存多份草稿 | 顶部「草稿箱」图标 → 「当前存为新草稿」；同一弹窗可备份/恢复全部数据 |
| 图片上传到图床 | 左栏「排版 → 图片上传」选择方式并保存 → 把图片拖进编辑区即可上传插入 |
| 导入现成文稿 | 左栏「排版 → 文件导入/导出 → 导入文件」（支持 .md / .html / .txt，自动识别 Markdown） |
| 导出交付 | 「导出 MD」/「导出 HTML」/「导出 PDF（打印）」 |

### 6.4 关于外部依赖
- **本项目零外网依赖**：KaTeX（公式）与 Mermaid（图表）已作为**内置离线包**放在 `vendor/` 目录；
- KaTeX 的 20 个字体文件已 **Base64 内嵌** 进 `katex.min.css`，因此连 `file://` 双击打开也不会被浏览器 CORS 拦截；
- 加载策略：优先本地 `vendor/`，仅当本地资源缺失时才回退 jsDelivr / unpkg CDN；两者都失败则保留公式/图表原文；
- 其余能力（Markdown 解析、代码高亮、排版、模板、AI、图床）均为纯本地实现。

### 6.5 注意事项
- 微信公众号后台粘贴时会丢弃 class 样式，**务必先点「一键内联样式」**；
- 图片需在公众号后台重新上传（微信不接受外部地址与本地 base64）；
- AI 配置、草稿、模板、风格全部只存在本机浏览器，清除浏览器数据会丢失。

## 七、风险与约束

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| CORS 跨域 | 浏览器直接抓取 135 编辑器模板可能被拦截 | 保留「粘贴源码」导入通道 |
| 图片跨域 | 内置生图接口返回图片地址，直接 fetch 转 base64 可能被 CORS 拦截 | 失败时降级为直接使用图片 URL |
| 微信图片 | 微信后台不接收外部/本地 base64 图片 | 复制后需在微信后台「重新上传」图片，文档与界面给出提示 |
| AI Key 安全 | Key 存于浏览器本地 | 仅本地存储、不外传，界面明确提示 |
| 存储容量 | localStorage 约 5MB，图片过多会写满 | 捕获异常并提示清理 |
